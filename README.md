## 写作与阅读偏好（后续修改请遵循）

以下是本资料库维护者明确提出的偏好，适用于后续补充、重写和整理。继续工作前，先阅读本节与对应专题的 README；有新的明确要求时，以新要求为准，并同步更新这里。

### 用人话解释，保持技术准确

先说清楚在解决什么问题，再解释方法为什么有用，最后给出公式和细节。使用自然、直接的中文，避免故作高深、堆砌术语或戏剧化措辞。

比喻和具体例子用来帮助理解，但随后要回到真实机制。不要把比喻当作证明，也不要用“必然”“完美”“终极”等表述代替条件和证据。

### 概念先铺垫，再使用

非基础概念在第一次使用前或使用时解释：它是什么、为什么在这里需要它，以及与前面内容有什么关系。缩写首次出现时给出名称和简明含义，不要求读者自己补齐前置知识。

公式附近解释符号、单位、取值与适用条件。章节按照依赖关系组织，避免后半篇突然出现前面没有介绍的概念；不影响主线的复杂推导可以移入数学补充。

### 排版要有呼吸感

每段围绕一个主要意思，避免连续堆积长段落。段落、小节、公式和插图之间保留充分留白；用分层标题帮助定位，避免大块加粗和过密的列表或表格。

图前说明要观察什么，图后解释看到的结果。公式单独成行时，配套说明也应分段呈现，不把公式、术语解释和结论挤成一块。

需要长时间阅读的专题，可同时维护 HTML 阅读版，提供舒适的字号、行距、正文宽度和窄屏适配。当前阅读版约 19px 正文、1.9 倍行距可作为起点，具体数值以实际可读性为准。

### 简单插图直接用 Python 代码绘制

对于比较简单的插图，直接用 Python 代码绘制，例如基础曲线、旋转几何示意和方法对比图，避免为简单需求引入复杂工具流程。

复杂插图根据内容、可编辑性和交付格式选择合适工具，不统一限定为 Python。保留生成代码或可编辑源文件，方便后续修改。

图中注明必要的参数、单位与来源。教学示意、人工模拟和模型实测结果要明确区分；修改相关正文或参数时，同步更新图和图注。

### 资料按专题组织，便于持续积累

根目录维护总入口，专题目录维护阅读顺序和文件说明。正文、相关插图与生成源码放在同一专题中；论文原文、实验记录和跨专题资源按下文规则归类。

重写时保留有价值的内容和完整原稿。整理不仅是改措辞，还要检查概念衔接、技术正确性和链接，必要时重排章节、重绘插图。

## 资料放在哪里

```text
大模型/
├── README.md                 资料入口与存放规则
├── notes/                    自己整理的知识笔记
│   ├── foundations/          基础机制：分词、位置编码、概率等
│   │   ├── rope-and-context/ 旋转位置编码与上下文扩展
│   │   └── tokenization/     Tokenization 与词表
│   ├── architecture/         模型架构：Attention、Transformer、MoE 等
│   │   └── attention/        Attention 与 MHA/MQA/GQA
│   └── systems/              系统机制：并行、量化、推理运行时等
├── infra/                    基础设施：训练集群、部署、监控、存储
├── papers/                   论文 PDF、补充材料与论文阅读笔记
├── experiments/              实验代码、配置、结果与运行记录
├── resources/                跨专题复用的资料、模板与数据说明
├── scripts/                  跨专题使用的工具脚本
└── archive/                  原稿、旧版本与不再维护的材料
```

`notes` 按知识层级和主题组织：基础机制放 `foundations`，模型结构放 `architecture`，系统机制放 `systems`。训练集群、部署和监控放 `infra`，不要把基础设施说明塞进模型原理专题。只有有实际资料时再增加更细的专题目录。

## 新资料的组织规则

**知识笔记以专题为单位。** 一个专题放一个文件夹，入口叫 `README.md`。正文超过几个大节时拆成带编号的章节，例如 `01-基础.md`。图片放在专题自己的 `assets/`，生成它们的代码放在 `src/`。

**论文以论文为单位。** 推荐 `papers/年份-短标题/`，里面放原文、来源链接和阅读笔记。笔记引用论文即可，不把同一个 PDF 复制到多个专题。

**实验以实验为单位。** 推荐 `experiments/日期-实验名称/`，至少记录目的、模型版本、配置、运行方法和结论。大型权重、数据集和缓存放在专门的数据盘位置，这里只记录路径与获取方法。

**原稿只归档，不继续修改。** 当前原稿保存在 [archive/originals](archive/originals/README.md)，后续正文以专题目录中的版本为准。
